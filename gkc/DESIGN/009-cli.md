# GKC-009 — CLI Architecture

> The `gkc` command-line interface: subcommand surface, UX philosophy, output contract, automation model, and exit-code semantics. This is the **only public API** of GKC.

---

## 1. Purpose

Define the CLI (C15) as a **stable, scriptable, automation-friendly** interface to every GKC capability. After this document, the CLI is implementable without ambiguity, and external systems (AIOS, IDEs, CI) can depend on its contract.

This document defines:

- the **subcommand surface** (what commands exist, forever),
- the **UX philosophy** (how commands behave for humans and scripts),
- the **output contract** (text, JSON, JSONL, exit codes),
- the **automation model** (CI integration, scripting),
- the **global flags** and **per-subcommand flags**,
- the **configuration model** (workspace config, profiles).

---

## 2. UX Philosophy

### 2.1 Principles

1. **Stable subcommands.** The set of subcommands is fixed; new commands require a major version bump. Plugins add flags to existing commands, not new commands (per `DESIGN/008`).
2. **One command, one job.** Each subcommand does one thing well. No "do everything" commands.
3. **Human by default, machine on request.** Default output is human-readable; `--format=json` switches to machine-readable.
4. **Deterministic output.** Same input + same flags ⇒ byte-identical output (excluding progress indicators on stderr).
5. **No silent failures.** Every failure produces a diagnostic and a non-zero exit code.
6. **Composable.** Commands can be piped; JSON output is structured for `jq`/`grep`.
7. **Local-first.** No command requires network access (per `DESIGN/001` § 7.8).

### 2.2 Output channels

- **stdout**: the command's primary output (results, structured data).
- **stderr**: diagnostics, progress, warnings.
- **exit code**: status (per § 5).

### 2.3 Progress

Progress indicators go to stderr and are suppressed when:

- `--format=json` is set.
- stdout is not a TTY (i.e., piped).

This keeps stdout clean for scripting.

## 3. Subcommand Surface (Canonical)

| Subcommand | Purpose | Maps to |
|---|---|---|
| `gkc scan` | Scan a repository and compile a snapshot | Pipeline stages 1–10 |
| `gkc registry` | Query the registry | C5, Q10 (find) |
| `gkc graph` | Emit a graph | C6/C7/C8, Q7 |
| `gkc validate` | Run validation against GENESIS invariants | C9, Q9 |
| `gkc explain` | Explain one artifact | C12, Q2 |
| `gkc context` | Build a context package for a task | C11 |
| `gkc search` | Full-text + metadata search | C12, Q1 |
| `gkc stats` | Aggregate stats and health | C12, Q8 |
| `gkc doctor` | Health check + diagnostics | All (observability) |
| `gkc cache` | Manage caches (snapshot, stage, context, query) | C13 |

Plus three management subcommands:

| Subcommand | Purpose |
|---|---|
| `gkc init` | Initialize a workspace |
| `gkc plugin` | Plugin management (install, list, info, uninstall, hash) |
| `gkc bench` | Run the reference benchmark (per ADR-Candidate-0008) |

**Total: 13 subcommands.** This set is fixed for the 1.x version series. Additions require major version bump.

## 4. Subcommand Specifications

### 4.1 `gkc scan`

- **Purpose**: Scan a repository and produce (or update) a snapshot.
- **Usage**: `gkc scan [path] [--incremental-from=<snap>] [--stages=<range>] [--plugins=<list>] [--fail-on-constitutional-violation]`
- **Default path**: current directory.
- **Default behavior**: full compile; produces a new snapshot in the workspace.
- **Output**: snapshot id (stdout, single line); diagnostics (stderr, ranked).
- **Exit codes**: 0 success, 2 compile error, 3 constitutional violation, 4 internal error.

### 4.2 `gkc registry`

- **Purpose**: Query the registry.
- **Subcommands**: `list`, `show <id>`, `find [--kind=...] [--authority=...] [--identifier=...]`, `history <id>`.
- **Output**: structured list of registry entries.
- **Exit codes**: 0 success, 1 user error, 4 internal error.

### 4.3 `gkc graph`

- **Purpose**: Emit a graph in text, JSON, or DOT.
- **Usage**: `gkc graph <kind>` where kind ∈ {authority, dependency, ontology}.
- **Flags**: `--format=text|json|dot`, `--filter=...`.
- **Exit codes**: 0 success, 1 user error, 4 internal error.

### 4.4 `gkc validate`

- **Purpose**: Run validation against GENESIS invariants.
- **Usage**: `gkc validate [--snapshot=<id>] [--severity=...] [--invariant=<id>]`.
- **Default**: validates the latest snapshot in the workspace.
- **Output**: ranked diagnostics.
- **Exit codes**: 0 no violations, 3 constitutional violations, 2 errors, 4 internal error.

### 4.5 `gkc explain`

- **Purpose**: Explain one artifact.
- **Usage**: `gkc explain <id> [--depth=<n>]`.
- **Output**: structured explanation (identity, metadata, authority, deps, refs, concepts, validation status).
- **Exit codes**: 0 success, 1 not found, 4 internal error.

### 4.6 `gkc context`

- **Purpose**: Build a context package for a task.
- **Usage**: `gkc context --task="<description>" [--snapshot=<id>] [--budget=<tokens>] [--provider=<id>] [--model=<profile>] [--target=<artifact_id>]... [--concept=<term>]...`.
- **Default budget**: from model profile; default 8000.
- **Default provider**: from model profile; default `markdown`.
- **Output**: the context package (stdout); metadata (stderr).
- **Flags**: `--verify` runs the sufficiency test after building; `--relevance-threshold=<f>`; `--include-dropped-summary`.
- **Exit codes**: 0 success, 2 budget too small / compile error, 4 internal error.

### 4.7 `gkc search`

- **Purpose**: Full-text + metadata search.
- **Usage**: `gkc search <query> [--kind=...] [--authority=...] [--namespace=...] [--limit=<n>]`.
- **Output**: ranked results.
- **Exit codes**: 0 success, 4 internal error.

### 4.8 `gkc stats`

- **Purpose**: Aggregate stats and health.
- **Usage**: `gkc stats [--snapshot=<id>] [--plugins]`.
- **Output**: counts by kind, authority, severity; index availability; plugin metrics.
- **Exit codes**: 0 success, 4 internal error.

### 4.9 `gkc doctor`

- **Purpose**: Health check.
- **Usage**: `gkc doctor`.
- **Output**: workspace health, plugin health, cache health, recent session metrics, any workspace-level warnings.
- **Exit codes**: 0 healthy, 1 warnings, 4 internal error.

### 4.10 `gkc cache`

- **Purpose**: Manage caches.
- **Subcommands**: `clear [--queries|--context|--stage|--snapshots]`, `prune` (LRU eviction to configured limit), `stats` (cache sizes, hit rates).
- **Exit codes**: 0 success, 1 user error, 4 internal error.

### 4.11 `gkc init`

- **Purpose**: Initialize a workspace.
- **Usage**: `gkc init [path]`.
- **Default path**: current directory.
- **Effect**: creates `<path>/.gkc/` with default config, empty `plugins/`, empty `snapshots/`, empty `cache/`.
- **Exit codes**: 0 success, 1 already exists, 4 internal error.

### 4.12 `gkc plugin`

- **Purpose**: Plugin management.
- **Subcommands**: `install <path>`, `uninstall <id>`, `list`, `info <id>`, `hash <dir>` (computes integrity hash).
- **Exit codes**: 0 success, 1 not found / conflict, 4 internal error.

### 4.13 `gkc bench`

- **Purpose**: Run the reference benchmark (per ADR-Candidate-0008).
- **Usage**: `gkc bench [--suite=default|large]`.
- **Output**: benchmark results (timings, throughput ratios).
- **Exit codes**: 0 success, 4 internal error.

## 5. Exit Codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | User error (invalid args, not found) |
| 2 | Compile error (parse failure, unresolved hard dep) |
| 3 | Constitutional violation (GENESIS invariant violated) |
| 4 | Internal error (unexpected exception, storage failure) |

Exit codes are stable across versions. New codes require a major version bump.

## 6. Global Flags

| Flag | Purpose | Default |
|---|---|---|
| `--workspace=<path>` | Workspace path | Current directory's `.gkc/` or parent |
| `--format=text|json|jsonl` | Output format | `text` |
| `--debug` | Verbose output to stderr; stack traces on internal errors | off |
| `--quiet` | Suppress info diagnostics | off |
| `--no-color` | Disable ANSI colors | auto (off if not TTY) |
| `--plugins=<list>` | Override plugin set for this invocation | workspace default |
| `--config=<path>` | Override config file | workspace default |
| `--version` | Print version and exit | — |
| `--help` | Print help and exit | — |

Global flags precede the subcommand: `gkc --format=json scan`.

## 7. Output Contract

### 7.1 Text output (default)

- Human-readable.
- Stable for scripting (same input + flags ⇒ same output).
- ANSI colors when stdout is a TTY (disable with `--no-color`).
- Tables for lists; indented sections for details.

### 7.2 JSON output (`--format=json`)

- Single JSON object per command invocation.
- Schema is self-describing (per ADR-Candidate-0001); includes `schema_version`.
- Deterministic key order (sorted).
- Pretty-printed by default; `--compact` for minified.

### 7.3 JSONL output (`--format=jsonl`)

- One JSON object per line.
- Suitable for streaming to `jq` or other tools.
- Used for: `gkc registry list`, `gkc search`, `gkc graph` (edges), `gkc validate` (diagnostics).

### 7.4 DOT output (graph subcommand only)

- Graphviz DOT format.
- Stable node and edge ids.

### 7.5 Schema stability

- JSON output schemas are versioned (per `DESIGN/004` § 3).
- Additive changes (new optional fields) are minor version bumps.
- Breaking changes (removed fields, type changes) are major version bumps.

## 8. Configuration

### 8.1 Workspace config

Located at `<workspace>/.gkc/config.json`:

```json
{
  "schema_version": "1.0.0",
  "default_model_profile": "claude-haiku",
  "default_token_budget": 8000,
  "default_context_provider": "markdown",
  "default_closure_depth": 3,
  "default_relevance_threshold": 0.1,
  "cache": {
    "max_size_gb": 5,
    "lru_enabled": true,
    "snapshot_retention_per_repo": 10
  },
  "plugins": {
    "capability_policy": {
      "allow": ["filesystem-read", "network-loopback"],
      "deny": ["network-external", "subprocess"],
      "require_explicit": ["filesystem-write", "env-read"]
    }
  },
  "sandboxing_level": "A"
}
```

### 8.2 Model profiles

Located at `<workspace>/.gkc/models/`:

```json
{
  "id": "claude-haiku",
  "context_window": 200000,
  "output_reservation": 4000,
  "tool_use": true,
  "token_estimator": "chars/4",
  "preferred_provider": "anthropic-xml"
}
```

### 8.3 Override precedence

1. Command-line flags.
2. Environment variables (`GKC_*`).
3. Workspace config.
4. Built-in defaults.

## 9. Automation Model

### 9.1 CI integration

- `gkc scan` in CI: produces a snapshot; exit 3 fails the build on constitutional violations.
- `gkc validate` in CI: validates an existing snapshot; exit codes drive CI decisions.
- `gkc context` in CI: produces a context package for an agent step.

### 9.2 Scripting

- JSON output is stable and scriptable.
- JSONL output streams to `jq` for filtering.
- Exit codes compose with shell `&&` / `||`.

### 9.3 IDE integration

- IDEs run `gkc` as a subprocess and parse JSON output.
- `gkc explain` powers tooltips; `gkc search` powers navigation; `gkc context` powers AI features.

### 9.4 AIOS integration

- AIOS uses the CLI's JSON output as its substrate contract (per ADR-Candidate-0038).
- No library API; the CLI is the contract.

## 10. Help Text

Every subcommand has:

- A one-line summary (`gkc <cmd> --help`).
- A usage line.
- A flags section.
- An examples section.
- A "See also" section linking to design docs.

Help text is generated from a single source of truth (the subcommand spec) to avoid drift.

---

## 11. Error Reporting

### 11.1 User errors (exit 1)

- Invalid args: usage message to stderr; exit 1.
- Not found: `not-found: <id>` to stderr; exit 1.

### 11.2 Compile errors (exit 2)

- Diagnostics to stderr in ranked order; exit 2.

### 11.3 Constitutional violations (exit 3)

- Diagnostics to stderr in ranked order; exit 3.

### 11.4 Internal errors (exit 4)

- Stack trace to stderr (if `--debug`); brief message otherwise; exit 4.
- Internal errors are bugs; users are directed to file an issue.

---

## 12. Versioning

- `gkc --version` prints `<major>.<minor>.<patch>`.
- Subcommand set is stable within a major version.
- Flag set is stable within a major version (additive only).
- Exit codes are stable forever.
- JSON output schemas are versioned per `DESIGN/004` § 3.
