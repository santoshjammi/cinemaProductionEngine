# GKC-009 — Engineering Review

> Adversarial review of `DESIGN/009-cli.md`.

## Review Stance

The reviewer is a CLI designer who has shipped tools used by millions and been burned by unstable output, ambiguous flags, and exit-code drift. They assume the CLI will be scripted on day one and that any instability breaks users.

## 1. Subcommand Surface Stability

- [ ] All 13 subcommands are listed and stable for the 1.x series.
- [ ] No subcommand overlaps another's responsibility.
- [ ] Every component from `DESIGN/003` is reachable via a subcommand.
- [ ] Plugin extension does not add subcommands (only flags).

## 2. UX Principles

- [ ] § 2.1 lists seven principles; each is enforceable.
- [ ] "Stable subcommands" is a hard constraint, not a guideline.
- [ ] "Deterministic output" is testable.
- [ ] "Local-first" matches `DESIGN/001` § 7.8.
- [ ] Progress suppression rules are explicit (§ 2.3).

## 3. Per-Subcommand Specifications

For each of the 13 subcommands (§ 4):

- [ ] Purpose is one sentence.
- [ ] Usage line shows arguments and flags.
- [ ] Default behavior is explicit.
- [ ] Output structure is defined.
- [ ] Exit codes are listed.

## 4. Exit Codes

- [ ] Five codes are defined (0, 1, 2, 3, 4).
- [ ] Codes are stable forever.
- [ ] Each code maps to a clear category.
- [ ] Constitutional violation (3) is distinct from compile error (2).

## 5. Global Flags

- [ ] Flag list is complete.
- [ ] Defaults are explicit.
- [ ] `--format` and `--workspace` are global (apply to all subcommands).
- [ ] `--debug` and `--quiet` are independent.

## 6. Output Contract

- [ ] All four formats are specified (text, JSON, JSONL, DOT).
- [ ] JSON schema is self-describing (per ADR-Candidate-0001).
- [ ] JSON key order is deterministic (sorted).
- [ ] JSONL is one-object-per-line.
- [ ] DOT is Graphviz-valid.
- [ ] Schema stability rules match `DESIGN/004` § 3.

## 7. Configuration

- [ ] Workspace config schema is complete.
- [ ] Model profile schema is complete.
- [ ] Override precedence (§ 8.3) is total and explicit.
- [ ] `GKC_*` environment variables are documented.

## 8. Automation Model

- [ ] CI integration is described with concrete examples.
- [ ] Scripting with JSON/JQ is supported.
- [ ] IDE integration is described.
- [ ] AIOS integration uses CLI JSON output (per ADR-Candidate-0038).

## 9. Help Text

- [ ] Every subcommand has help.
- [ ] Help is generated from a single source of truth.
- [ ] Examples are included.
- [ ] "See also" links to design docs.

## 10. Error Reporting

- [ ] All four error categories (§ 11) are specified.
- [ ] User errors print usage to stderr.
- [ ] Internal errors print stack traces only with `--debug`.
- [ ] No silent failures.

## 11. Versioning

- [ ] Version format is semver.
- [ | Subcommand set stable within major version.
- [ ] Flag set additive within major version.
- [ ] Exit codes stable forever.

## 12. Cross-Document Consistency

- [ ] Subcommands map to components in `DESIGN/003`.
- [ ] Output formats match `DESIGN/006` § 10.
- [ ] Plugin flags match `DESIGN/008` § 4.
- [ ] Storage paths match `DESIGN/010`.

## 13. Open Questions

- [ ] All five open questions are ADR candidates in `DECISIONS/009-cli-adr-candidates.md`.
- [ ] None block M0.

## 14. Document Quality

- [ ] No implementation code.
- [ ] No language-specific idioms.
- [ ] Reasonable length (target: under 1500 lines).

## 15. Exit Criteria

The document passes iff every checkbox is checked or addressed by an ADR candidate.
