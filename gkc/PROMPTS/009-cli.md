# GKC-009 — Engineering Prompt

## Objective

Implement the **CLI (C15)**: subcommand dispatch, global flags, per-subcommand flags, output formatting (text/JSON/JSONL/DOT), exit codes, help generation, configuration loading, and automation contract.

## Inputs

- `DESIGN/009-cli.md` (authoritative)
- `DESIGN/003-component-architecture.md` (§ C15 boundaries)
- `DECISIONS/009-cli-adr-candidates.md`

## Scope

1. **Argument parser** — parse global flags + subcommand + subcommand flags; reject invalid combinations with usage messages.
2. **Subcommand dispatch** — route to the 13 subcommands in § 3; each subcommand calls the appropriate component (C1–C14).
3. **Output formatters** — text, JSON, JSONL, DOT; deterministic key order; schema self-describing.
4. **Exit codes** — implement the 5-code scheme in § 5.
5. **Help generation** — generate help text from the subcommand spec (single source of truth).
6. **Configuration loading** — load workspace config, model profiles; apply override precedence (§ 8.3).
7. **Progress indicators** — stderr, TTY-aware, suppressed on `--format=json` or non-TTY.
8. **Error reporting** — implement § 11 for all four error categories.
9. **Shell environment** — read `GKC_*` environment variables per § 8.3.
10. **Plugin flags** — plugins may add `--<plugin-id>-<flag>` flags to existing subcommands (per `DESIGN/008` § CLI boundaries).

## Out of Scope

- Component implementations (use stubs from `DESIGN/003`).
- Shell completion scripts (deferred per ADR-Candidate-0049 if open).
- `gkc serve` mode (deferred per ADR-Candidate-0029).

## Done Conditions

- All 13 subcommands dispatch correctly to their components.
- Global flags work; per-subcommand flags work; invalid combos exit 1 with usage.
- All four output formats produce valid output (text stable; JSON schema-conformant; JSONL one-object-per-line; DOT graphviz-valid).
- Exit codes match § 5 for all error categories.
- Help text is generated from the spec (no drift).
- Configuration loads with correct override precedence.
- Progress is suppressed on `--format=json` and non-TTY.
- Determinism: same args + same workspace state ⇒ byte-identical stdout (excluding progress on stderr).

## Constraints

- Implementation language: per `DECISIONS/0010-implementation-language.md`.
- Use stdlib for argument parsing; no external CLI libraries (keeps the dependency surface small).
- No ANSI colors when stdout is not a TTY.
- No network access.

## Deliverables

- `cli/parser` — argument parser
- `cli/dispatch` — subcommand dispatch
- `cli/formatters/{text,json,jsonl,dot}` — output formatters
- `cli/exit-codes` — exit code definitions
- `cli/help` — help generation
- `cli/config` — configuration loading
- `cli/progress` — progress indicators
- `cli/errors` — error reporting
- `cli/env` — environment variable handling
- `cli/tests/*` — per-subcommand and cross-cutting tests

## Verification

1. `gkc test cli` — all CLI tests pass.
2. `gkc --version` prints a version string.
3. `gkc scan --help` prints help with usage, flags, examples.
4. `gkc scan gold/empty` produces a snapshot id on stdout.
5. `gkc scan gold/empty --format=json` produces valid JSON on stdout; no progress on stderr.
6. `gkc scan --invalid-flag` exits 1 with usage to stderr.
7. `gkc explain <nonexistent-id>` exits 1 with `not-found`.
8. `gkc scan gold/drifted-repo` exits 3 with constitutional violation diagnostics.
9. Determinism: `gkc scan gold/empty` twice produces byte-identical stdout.

Report pass/fail per step. Any failure blocks M0.
