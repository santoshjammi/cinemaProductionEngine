# Legacy Re-Adoption Protocol

**Version:** 1.0

## Purpose

Prevent old contradictory documentation from re-entering the authoritative system through convenience.

## Rule

A legacy rule from `unimportant_docs` has no authority until re-adopted.

## Required process

```yaml
legacy_re_adoption:
  legacy_source_path:
  legacy_rule_summary:
  why_it_is_still_useful:
  conflicts_with_current_docs:
  target_document:
  target_classification:
  proposed_change:
  migration_impact:
  approved_by:
```

## Questions before adoption

1. Is the idea still needed?
2. Is it already represented more cleanly?
3. Does it belong in a constitution, standard, ontology, schema, or implementation?
4. Does it reintroduce duplicate ownership?
5. Does it depend on an outdated provider or architecture?
6. Does it conflict with current Psychology/Mark & Sarah direction?

## Example

Legacy idea:
> “Character Visual DNA must remain consistent.”

Decision:
- still useful;
- does not need a new constitution;
- adopt into `VISUAL_CHARACTER_CONTINUITY_STANDARD.md` and visual identity registry.

Legacy idea:
> “GENESIS Image Generator Agent generates production images.”

Decision:
- conflicts with Cinema Master Constitution;
- reject;
- production image generation belongs to PROMETHEUS.
