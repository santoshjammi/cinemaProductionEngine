# Visual Character Continuity Standard

**Version:** 1.0

## Principle

A recurring character is an identity-controlled asset, not a fresh prompt.

## Identity lock

For Mark & Sarah, production must use approved visual references from the series registry.

The reference asset outranks prose such as:

> “handsome 40-year-old white American software engineer.”

Prose is descriptive. The reference is identity.

## Must remain consistent

- facial identity;
- apparent ethnicity;
- approximate age;
- key hair identity;
- body proportions within reasonable generation tolerance;
- distinguishing facial features.

## May vary

- expression;
- angle;
- lighting;
- context-appropriate wardrobe;
- posture;
- location;
- emotional state.

## Wardrobe continuity

Within a continuous scene/time block, wardrobe changes require narrative cause.

## Location continuity

Recurring home/work spaces should have reusable environment references when possible.

## Failure rule

If a viewer could reasonably believe a shot depicts a different actor, the shot fails.

## Example

A beautiful generated frame that does not look like approved Sarah is not “close enough.”

It is a rejected Sarah asset.

## Production implication

PROMETHEUS should preserve:

- reference image IDs;
- identity-control inputs;
- seeds where useful;
- model/workflow version;
- generated asset hash.

ORACLE should compare against reference identity, not only against neighboring generated frames.
